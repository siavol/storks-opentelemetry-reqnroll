# SUT в тестах запускается out-of-process через Aspire.Hosting.Testing

Сценарии гоняются против SUT, поднятого из того же AppHost, что и при ручном запуске (Orders, Pricing, Postgres), а не против in-process `WebApplicationFactory`. Поэтому плагин не может встроиться в OTel SDK приложения и получает телеметрию по OTLP: в тестовом процессе работает OTLP-приёмник, и ресурсы AppHost экспортируют в него. Выбрали этот путь, потому что он реалистичнее и не требует отдельной тестовой инфраструктуры (Testcontainers).

## Consequences

- Ядро плагина работает с собственной нейтральной моделью span/log. OTLP — лишь один из источников; in-process источник можно добавить позже без изменения ядра. Маппинг OTLP → нейтральная модель живёт только в приёмнике (`Receiver/`); индекс атрибуции строится по нейтральной модели из хранилища. Лог ссылается на свою исходную запись непрозрачным id, который даёт источник: у OTLP-приёмника это позиция записи среди принятых запросов, по ней Telemetry Viewer находит запись во встроенном OTLP/JSON (ADR 0002).
- Сбросить батч экспорта другого процесса нельзя: у ресурсов уменьшается интервал экспорта, а всё, что видит пользователь, плагин строит в конце прогона, после остановки AppHost, когда процессы SUT уже отправили остатки. Пауз в хуках и в конце прогона нет (тикет 09). Если тестовый проект не останавливает SUT в AfterTestRun, телеметрия последних миллисекунд может не успеть.
- AppHost стартует один раз на прогон, а не на сценарий.
